# SynapseHSG

Structured Multimodal Question Answering over Academic Presentations via Hypergraph Semantic Graphs.

## Setup

```bash
pip install -r requirements.txt
cp .env.example .env
# Edit .env with your API endpoints
```

Requires an OpenAI-compatible API serving a model such as Qwen3.6-27B, and a BGE-M3 embedding endpoint.

## Running the Pipeline

### End-to-end (raw data → answers)

```bash
source .env

python -m pipeline \
  --raw-data /path/to/raw_data \
  --golden-data dataset/gold_test.jsonl \
  --decomposer-path models/decomposer_qwen35_9b/final \
  --gen-model Qwen3.6-27B \
  --use-hyperedge-anchor \
  --use-linearize \
  --output results.json
```

`--raw-data` triggers HSG construction first, then runs retrieval/generation/evaluation.

Raw session directories should follow:
```
raw_data/
  {conference}/
    {session_id}/
      metadata.json
      paper.pdf
      slides/
        0001.png
        0002.png
        ...
      audio.mp3   # optional
```

### On existing HSG output

```bash
python -m pipeline \
  --data-root hsg_output/run_YYYYMMDD_HHMMSS \
  --golden-data dataset/gold_test.jsonl \
  --decomposer-path models/decomposer_qwen35_9b/final \
  --gen-model Qwen3.6-27B \
  --use-hyperedge-anchor \
  --use-linearize \
  --output results.json
```

### Standalone HSG construction

```bash
python -m pipeline.build_hsg \
  --root /path/to/raw_data \
  --output /path/to/hsg_output

# Resume interrupted run
python -m pipeline.build_hsg --root /path/to/raw_data --resume-latest
```

### Key Flags

| Flag | Description |
|------|-------------|
| `--raw-data` | Raw data root; triggers HSG construction before inference |
| `--data-root` | Path to HSG output (used when skipping construction) |
| `--decomposer-path` | Path to trained decomposer LoRA model |
| `--golden-data` | Path to QA test set (JSONL) |
| `--gen-model` | Generation model name |
| `--use-hyperedge-anchor` | Enable hyperedge-based expansion anchor |
| `--use-linearize` | Use graph-linearized context for generation |
| `--use-learned-reranker` | Use precomputed MLP scores for reranking |
| `--no-decomposer` | Skip decomposer, use raw question |
| `--no-hsg` | Skip HSG, use flat text retrieval |
| `--max-samples` | Limit evaluation samples |
| `--skip-eval` | Generate answers only, skip LLM evaluation |

### MLP Edge Score Precomputation

`--use-learned-reranker` requires a precomputed score cache. The pipeline reads scores from a JSON file produced by `precompute_mlp_scores.py`:

```bash
python pipeline/precompute_mlp_scores.py \
  --data-root hsg_output/run_YYYYMMDD_HHMMSS \
  --model-dir models/mlp_full \
  --output dataset/output/mlp_edge_scores.json
```

Without this step, omit `--use-learned-reranker` and the pipeline uses semantic reranking by default.

## Training

### Decomposer (Qwen3.5-9B + LoRA)

The decomposer maps a question to a structured JSON decomposition. Training data is generated by prompting an LLM to decompose each question in the dataset, then fine-tuning Qwen3.5-9B on the collected question→decomposition pairs.

```bash
python train/train_decomposer.py \
  --train-data train/decomposer_train.jsonl \
  --dev-data train/decomposer_dev.jsonl \
  --output-dir models/decomposer_qwen35_9b \
  --base-model Qwen/Qwen3.5-9B \
  --epochs 3 --lr 2e-4 --batch-size 4
```

### MLP Edge Scorer

The MLP reranker predicts edge quality from heuristic features. Training data is assembled from HSG output — each triple is labeled with its heuristic tier (strong/medium/weak) and augmented with hard negatives.

```bash
# Step 1: Assemble supervision data from HSG triples
python train/assemble_supervision.py \
  --run-dir hsg_output/run_YYYYMMDD_HHMMSS \
  --output-dir train/supervision

# Step 2: Train MLP
python train/train_mlp.py \
  --supervision-dir train/supervision/ \
  --output-dir models/mlp_full
```

## Evaluation

The pipeline evaluates using LLM-as-judge on answer correctness (for answerable questions) and refusal accuracy (for unanswerable questions).

```bash
python -m pipeline \
  --data-root hsg_output/run_YYYYMMDD_HHMMSS \
  --golden-data dataset/gold_test.jsonl \
  --decomposer-path models/decomposer_qwen35_9b/final \
  --gen-model Qwen3.6-27B \
  --use-hyperedge-anchor \
  --use-linearize \
  --output eval_results.json
```

Results are written as JSON with per-sample scores and aggregate metrics (accuracy, answerable correct rate, unanswerable refusal rate).

### Re-evaluation with GPT

To re-evaluate existing results with a different judge model:

```bash
python eval/reeval_baseline_gpt.py \
  --input previous_results.json \
  --output reeval_results.json \
  --model gpt-4o
```

## Project Structure

```
SynapseHSG/
  requirements.txt
  .env.example
  pipeline/
    build_hsg.py            # HSG construction entry point
    run_pipeline.py          # Unified pipeline (end-to-end)
    m2hsg/                   # HSG construction module
    precompute_mlp_scores.py # MLP score precomputation
    constructor.py           # HSG graph construction
    retriever.py             # Multi-channel retrieval
    reranker.py              # Semantic reranking
    evaluator.py             # LLM-based evaluation
  train/
    train_decomposer.py      # Decomposer training
    train_mlp.py             # MLP training
    assemble_supervision.py  # Assemble MLP supervision from HSG output
  dataset/
    train.jsonl
    gold_dev.jsonl
    gold_test.jsonl
  baseline/                  # Comparison baselines
  eval/                      # Evaluation utilities
```
